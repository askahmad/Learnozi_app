2.  Project Information:
Project Title
Learnozi – Intelligent Academic Assistant & Study Companion
Project Type
Applied Project
Domain/Tools
Domain: Educational Technology (EdTech), Applied Artificial Intelligence (AI), and Full-Stack Web Engineering.
Tools: React.js (Vite) for the frontend; Node.js (Vercel serverless functions) for the backend; Supabase (PostgreSQL database, authentication, and file storage); Google Gemini API (LLM); Python, scikit-learn, and Google Colab for the self-trained weak-topic model; Vercel for hosting; Git/GitHub and Postman.
Functional Requirements
1.  User Authentication & Profile Management: Registration with name, optional profile photo, and email. School students choose their grade (9, 10, 11, 12) and course (Medical, Computer, Commerce, or Engineering); university students give their university name, semester, and program. The email address is verified with a one-time password (OTP). Login uses email, password, and a CAPTCHA. A forgotten password is reset through a link sent to the verified email. Sessions are secured with tokens and users can log out safely.
2.  AI Academic Concept Explainer: A chat tutor that explains any topic step by step with examples and a short revision summary, adapted to the student's grade or program. The student can type, attach an image (optional), or speak (voice-to-text). Explanations are available in English and Urdu.
3.  Document Chat & Note Summarizer: The student uploads notes, a PDF, or an image (maximum 5 MB). The system produces a summary and key points. Every uploaded document has its own separate chat, shows how much of the document has been used in the conversation, and, for technical material, gives code in the programming language of the document.
4.  AI Auto-Quiz & Assessment Generator: Quizzes are generated from a topic or an uploaded document in Short, Long, MCQ, or Mixed format using an LLM prompt-engineering pipeline, and answers are checked on the spot. While a quiz is open, the student cannot switch to another chat; closing or leaving the quiz terminates it. Quiz progress is shown on the top bar and on the dashboard.
5.  Adaptive Learning & Weak-Topic Diagnostic Engine: Quiz performance is tracked continuously for each topic. A machine-learning model trained by the team (scikit-learn) identifies weak topics, and the difficulty and focus of later quizzes and revision recommendations are adjusted accordingly.
6.  Active Recall Flashcard System: Flashcards can be created, categorized, and reviewed interactively. Reviews are scheduled with a spaced-repetition rule so that harder cards return sooner.
7.  Smart Study Planner & Milestone Scheduler: A dynamic timetable is built from the student's subjects and exam dates, with daily study targets and milestone tracking toward each exam.
8.  Integrated Pomodoro Focus Timer: A customizable study and break timer (default 25 and 5 minutes) with session logging and productivity streaks.
9.  Student Community & Peer Collaboration Hub: A discussion forum where students ask questions, reply, exchange study resources, mark doubts as resolved, and flag inappropriate posts.
10.  Analytics Dashboard & Accessibility: Charts of study hours, accuracy trends, and syllabus coverage; full English/Urdu support; and low-bandwidth optimization so the platform works on slow connections.
11.  Admin Panel & Usage Monitoring: An administrator-only panel showing the number of registered students, the number of uploaded files, and AI API usage, and allowing review and hiding of flagged community posts.
12.  Chat & Quiz History: Students can return at any time to their earlier AI Tutor chats, document chats, summaries, and past quiz results.
13.  Export / Download as PDF (secondary priority): A summary or quiz can be downloaded as a PDF for offline reading.
14.  Usage Limits (Daily Quota): Each user has daily limits on the free plan (for example, 10 AI requests and 3 document uploads per day) with a clear message and reset time when a limit is reached. This controls AI API cost and supports the freemium business model.
15.  Gamification: Streaks & Badges (secondary priority): A daily learning streak and achievement badges (for example, a Quiz Master badge after passing five quizzes) to keep students motivated.
16.  Error Handling & AI Feedback: The application handles AI failures, oversized files, and invalid input with clear messages instead of crashing, and every AI answer has a thumbs up / thumbs down option so the quality of the AI can be monitored and improved.
Abstract
Learnozi is an AI-powered adaptive learning platform built for Pakistani students preparing for Matric, FSc, MDCAT, and CSS examinations, as well as university students. General-purpose AI chatbots are not aware of local curricula, and most test-preparation tools use static question banks that are the same for every student. Learnozi bridges this gap by combining a syllabus-aware AI tutor, automatic quiz generation from a topic or from the student's own notes, and a self-trained machine-learning model that finds each student's weak topics and adapts later quizzes and revision.
The platform is built with React.js (Vite) and Node.js, uses Supabase (PostgreSQL, authentication, and file storage) for data, and is deployed on Vercel. The Google Gemini API provides language understanding and generation, while a scikit-learn model trained by the team performs weak-topic diagnosis. Supporting tools include spaced-repetition flashcards, a smart study planner, a Pomodoro focus timer, a peer community, chat and quiz history, PDF export, streaks and badges, and an analytics dashboard. Daily usage limits keep AI consumption sustainable, and an administrator panel allows monitoring of users, uploads, and AI usage.
Aligned with the Higher Education Commission's ICT-for-education priority, Learnozi offers English and Urdu support and is optimized for low-bandwidth conditions, aiming to make personalized, high-quality exam preparation available to students across Pakistan and not only to those who can afford private tutoring.

  "questions": [
    {
      "type": "mcq | short | long",
      "question": "question text",
      "options": ["A ...", "B ...", "C ...", "D ..."],   // mcq only
      "answer": "correct option or model answer",

      "topic_tag": "sub-topic name"
    }
  ]
}
Answer-grading prompt for short and long questions
Question: {question}
Model answer: {answer}
Student answer: {student answer}
Return ONLY JSON: {"score": a number from 0 to 1, "feedback": "one short sentence"}
Rules to follow for every AI call
Always parse and validate the JSON (right number of questions, required fields present). If it is invalid, retry once, then show a friendly error.
Use a low temperature for quizzes so the format stays stable.
Never call Gemini from the browser, and never print or log the API key.
For document chat, tell the model to answer only from the document, so answers stay grounded.
Log every call in ai_usage_log and count it in usage_counters.
Spaced-repetition rule (SM-2) for flashcards
Each card stores an ease factor (start 2.5) and an interval in days. After a review with rating q (0 to 5): if q is below 3, set the interval to 1 day. Otherwise the interval is 1 day for the first success, 6 days for the second, and then previous interval multiplied by the ease factor, rounded. Update the ease factor as EF = EF + (0.1 - (5 - q) x (0.08 + (5 - q) x 0.02)) and never let it fall below 1.3. The next review date is today plus the interval.
G. The Self-Trained Weak-Topic Model
Your supervisor asked for a model that you train yourselves, linked to the Gemini API. This is the part that proves your own AI work, so build it carefully and be honest about its data.
1.  Define the task: for each student and topic, predict whether the topic is weak (1) or not weak (0).
2.  Choose the input features: number of questions attempted, accuracy, average time per question, and days since the last attempt.
3.  Prepare data. At the start there will be no real students, so write a small script that generates a few thousand realistic rows (labelled by a rule with some random noise) so you can build the whole pipeline. Later, export real rows from your database and retrain. In the report and the viva, say clearly that the first data was simulated and that real data refines the model.
4.  Train in Google Colab with scikit-learn: split into training and test sets, train a Decision Tree and a Random Forest, and compare accuracy, precision, recall, F1-score, and the confusion matrix. Choose the better model and note which features matter most.
5.  Save the model with joblib (keep the file small) and place it in the ml/ folder.
6.  Serve it with a small Python function on Vercel (/api/adaptive/predict) that loads the model and returns the weak/not-weak flags for the topics sent to it.
7.  Connect it: after each quiz submission, call the function, write the result into topic_performance (weak_flag and predicted_level), show weak topics on the dashboard, and add them to the next quiz prompt.
8.  Keep the rule-based version as a fallback if the model function is unavailable.

SQL you will need (use these inside your functions)
The symbols $1, $2, and so on stand for values your code supplies.
Daily usage counter (create or add one, and return the new count)
INSERT INTO usage_counters (user_id, usage_date, ai_chats)
VALUES ($1, CURRENT_DATE, 1)
ON CONFLICT (user_id, usage_date)
DO UPDATE SET ai_chats = usage_counters.ai_chats + 1
RETURNING ai_chats;
Update topic performance after a quiz
INSERT INTO topic_performance (user_id, subject, topic, attempts, correct, accuracy)
VALUES ($1, $2, $3, $4, $5, $5::numeric / $4)
ON CONFLICT (user_id, subject, topic)
DO UPDATE SET
  attempts = topic_performance.attempts + EXCLUDED.attempts,
  correct  = topic_performance.correct  + EXCLUDED.correct,
  accuracy = (topic_performance.correct + EXCLUDED.correct)::numeric
           / (topic_performance.attempts + EXCLUDED.attempts),
  updated_at = now();
Daily streak
UPDATE profiles
SET current_streak = CASE
      WHEN last_active_date = CURRENT_DATE     THEN current_streak
      WHEN last_active_date = CURRENT_DATE - 1 THEN current_streak + 1
      ELSE 1 END,
    last_active_date = CURRENT_DATE
